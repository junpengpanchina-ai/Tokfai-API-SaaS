## 4. 五类证据链

### 4.1 飞控证据链

核心链路：

```text
任务目标 -> 飞控能力 -> 姿态控制 -> 分配/mix -> 电机输出 -> 安全边界
```

Tokfai 要证明的不是“无人机很强”，而是客户材料里是否能解释：

- 姿态控制入口在哪里
- 控制量如何分配到电机
- 是否存在限幅
- 异常时是否进入保护逻辑
- 审批材料里能否讲成人能理解的飞控说明

### 4.2 姿态证据链

核心链路：

```text
姿态误差 -> 角速度反馈 -> 控制修正 -> 虚拟控制量 -> 电机分配
```

可交付重点：

- 姿态误差来源
- 控制修正逻辑
- 是否存在 yaw / roll / pitch 方向解释
- 是否能从代码或日志里形成 Evidence Row

### 4.3 环境证据链

商业无人机不能只讲参数，必须讲环境适应：

- 高温
- 低温
- 强风
- 弱 GNSS
- 复杂地形
- 起降场地受限
- 任务中断

战争无人机能在高温、低温、复杂战场执行任务，本质不是玄学，而是工程可靠性证据：材料、飞控、链路、电池、任务规划、安全边界共同支撑。

商业无人机要进入审批场景，不能只说“能飞”，要证明“在什么条件下能飞，什么条件下不能飞，异常时如何处置”。

### 4.4 链路证据链

核心链路：

```text
遥控链路 -> 图传链路 -> GNSS/RTK -> 任务状态 -> 异常处置 -> 飞行结果
```

可交付重点：

- 哪个链路弱
- 哪个链路断
- 是否触发返航 / 悬停 / 降落 / 中止
- 客户材料是否有日志支撑
- 审批材料是否能解释链路风险

### 4.5 安全边界证据链

安全边界不是口号，是条件表：

| 条件 | 动作 |
|---|---|
| 风速超过阈值 | 不起飞 / 中止任务 |
| GNSS 降级 | 降级飞行 / 返航 / 悬停 |
| 电量低 | 返航 / 降落 |
| 姿态异常 | 限幅 / 中止 |
| 任务区域不一致 | 不提交 / 补件 |

## 5. 已经能支持补件的证据

当前样例材料已经可以支持：

1. 审批驳回原因表
2. 飞控 / 姿态控制解释稿
3. 环境适应性说明

这说明 Tokfai 已经不是单纯 API 中转，而是可以把客户文件、代码、日志、审批文本转成工程化证据链。

## 6. 仍然不足，不能承诺审批一定通过

不能承诺审批一定通过，原因：

1. 审批结果由监管部门判断，不由 Tokfai 决定。
2. 当前样例是合成 demo，不是真实客户完整材料。
3. 缺少真实飞控源码完整上下游。
4. 缺少真实飞行日志原始文件。
5. 缺少真实审批系统反馈全文。
6. 缺少客户设备型号、载荷、电池、链路、场地、任务时间等完整字段。

Tokfai 的定位是：

```text
提高材料完整度
提高证据链清晰度
提高补件效率
降低客户和审批沟通成本
不承诺审批一定通过
```

## 8. 客户演示话术

不能这么说：

```text
我们可以保证审批一定通过。
我们能解决所有飞行审批问题。
我们比监管更懂审批。
```

应该这么说：

```text
我们先不承诺审批结果。
Tokfai 做的是把你们现有材料拆成审批看得懂的证据链。
我们会先找出材料缺口，再把飞控、姿态、环境、链路、安全边界解释清楚。
最后交付的是补件清单、证据链、风险说明和客户可复盘材料。
审批是否通过，仍由主管部门判断。
```

```text

```

这就是无人机商业化场景里最值钱的部分。
