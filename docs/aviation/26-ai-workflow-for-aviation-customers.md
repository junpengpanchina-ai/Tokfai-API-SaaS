## 1. 工作流总则

```text
客户本地 workspace  ──Read/Search/Shell──►  old Codex CLI
                                              │
                                    OpenAI-compatible /v1
                                              ▼
                                           Tokfai
                                              │
                                      上游模型（推荐 gemini-3-pro）
```

- 客户源码、试验包、日志**留在客户磁盘**。  
- Tokfai **不执行**本地工具，**不**把工程树存成服务端副本。  
- 输出：路径、函数名、控制逻辑摘要、标明的工程推断、风险点、适航材料**线索**。  
- **禁止**完整源码正文。  
- 第一场禁止自由全库搜索 + 超长 prompt。

P1240-R3 已证明：在 **fixed-file-scope** 下，模型可基于本地读取走出 synthetic 链：

```text
txg_control_task.c
  → attitude_control_entry
  → rotor_law_update
  → control_allocation
  → actuator_command_write
```

客户工程以当场工具命中为准。

## 3. Tokfai 可切入的 AI 工作流

每个工作流都遵守：固定范围、分段、本机工具、证据类型标注。

### W1 工程文件读取

**痛点：** 关键逻辑只在个别工程师头脑中。  
**做法：** 指定 1–4 个文件，强制 Read，列出路径。  
**成交：** 10 分钟内出现真实路径。  
**禁止：** “我已读取”而无工具记录。

### W2 调用链追踪

**痛点：** 姿态 → 分配 → 执行器说不清。  
**做法：** 分段 S1–S4（SOP §6）。  
**已验证形态：** 上节 P1240 链。  
**禁止：** 凭函数名编 mixer 矩阵。

### W3 需求–设计–代码–测试映射

**痛点：** 适航/质量要追溯，仓库没有双向链。  
**做法：** 客户给出需求 ID 或试验科目名 + 少量代码/试验文件；输出对照表（ID | 路径 | 函数 | 证据类型 | 缺口）。  
**禁止：** 自动声称 DO-178/适航符合。

### W4 适航材料摘要

**痛点：** 包很大，评审读不完。  
**做法：** 本机打开**客户指定**的说明/矩阵章节，产出结构摘要与缺失项提问。  
**禁止：** 代写正式符合性声明、保证过审。

### W5 测试日志解释

**痛点：** HIL/试飞记录只有数值。  
**做法：** 指定日志片段 + 相关 1–2 个源文件，解释“哪类控制器输出异常”级别，标推断。  
**禁止：** 把摘要当事故调查结论。

### W6 飞行异常复盘

**痛点：** 夜间排故。  
**做法：** 时间戳 + 模式 + 固定模块文件；输出时间线假设与待查路径。  
**禁止：** 责任认定、对监管瞒报建议。

### W7 UOM / 运行申请材料准备辅助

**痛点：** 字段不会填、退回看不懂。  
**做法：** 对照 [25](./25-certification-and-operation-chain.md) 做缺口清单；把“识别/动态数据/应急”追到工程路径。  
**禁止：** 代登录、代提交、承诺批准。

### W8 客户内部知识库问答

**痛点：** ICD、规程、培训材料分散。  
**做法：** workspace 指向规程目录（非源码亦可）；引用文件路径作答。  
**禁止：** 把内部规程同步到 Tokfai 服务器。

## 6. 演示问题清单（可直接念）

**W1/W2（默认第一场）**

1. 请只 Read 这四个路径，列出姿态入口函数。  
2. `rotor_law_update`（或客户符号）的输入输出在文件中如何命名？  
3. 控制分配如何映射到通道？没有的写 NOT_IN_FILE。  
4. 执行器写出函数路径是什么？串成一张调用链表，区分文件证据与推断。

**W3/W4**

5. 该需求 ID 在矩阵里指向哪些文件路径？找不到就写找不到。  
6. 指定适航章节的结构摘要（无源码、无保证）。

**W5/W6**

7. 这段日志里与分配输出相关的时间点，对应哪个函数线索？  
8. 应急/RTH 相关符号在指定文件中是否出现？

**W7/W8**

9. 动态数据字段在 ICD 哪一页/哪个路径？  
10. 内部飞行申请检查单缺哪几项（对照客户自己的单，不编局方目录）？

## 7. 销售问法

1. 第一场能否把仓库缩到 ControlLaw + Actuator 四个文件？  
2. 适航代表最想看到的是调用链、矩阵缺口，还是日志解释？  
3. 日志和源码是否在同一台演示机上？  
4. 是否接受 Codex CLI 而不是聊天网页贴代码？  
5. 成功标准是“出现路径表”还是“给我们出正式意见”？（只接受前者作为 Tokfai 成交）  
6. 后续扩围是导航、BMS 还是 UOM 材料？一次只加一个域。

## 8. 成交抓手

| 抓手 | 用法 |
| ---- | ---- |
| P1240 已验证链 | 证明不是 PPT；同时声明是 synthetic 形态 |
| SOP 分段 | 降低现场失败率 |
| 报告模板 | [23](./23-customer-demo-sop.md) §7 可当场填 |
| 本机原则 | 过安全/法务 |
| 工作流菜单 | 飞控做完卖日志/矩阵，而不是卖“无限 Token” |
| 与容量叙事分离 | 不把 P1231 并发当飞控客户第一需求 |

## 9. 风险边界

| 风险 | 控制 |
| ---- | ---- |
| 幻觉调用链 | 无 Read 则 FAIL；见 SOP 验收 |
| 把摘要当符合性 | 每页重复禁止承诺 |
| Simulink 二进制 | 可能读不出；改生成代码或报告 PDF |
| 日志格式专有 | 先确认 CLI 能打开 |
| 扩范围超时 | 坚持四文件 |
| 工具流模型选错 | 推荐 `gemini-3-pro`；见 Codex runbook |

## 10. 禁止承诺

```text
禁止承诺 Tokfai 执行客户本地工具
禁止承诺上传或托管客户源码
禁止承诺自动通过适航/运营审定
禁止承诺事故调查或法律责任意见
禁止承诺与客户函数名/目录与 synthetic 一致
禁止承诺全库智能审查作为默认交付
禁止输出完整源码、key、Authorization、apiKeyId、canary、原始日志正文
禁止把模型口头“已读文件”当作交付
```
