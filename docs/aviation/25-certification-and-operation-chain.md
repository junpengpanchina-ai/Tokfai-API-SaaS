## 1. 一条链，不是一张证

客户说“适航/低空/UOM”时，拆成并行链。缺一环都会被口语说成“飞不了”（[06](./06-why-cannot-fly-taxonomy.md)）。

```text
产品身份     实名登记 / 唯一识别 / 激活          G2
航空器分类   微轻小中大                          G1
适航         需要则 TC/PC/AC 或过渡特殊适航      G3
人员         操控员资质                          G4
运行人       开放 / 特定 / 审定 + 运营合格证     G5
保险         责任保险                            G6
系统连接     UOM / 识别 / 动态数据 / C2          G7
空域         适飞 vs 管制 + 高度                 G8
飞行活动     申请 / 起飞前确认（如适用）          G9
任务         危险品/集会等额外许可                G10
持续运行     构型、维修、运行控制                 G11
```

演示时用这条链做**问诊顺序**，不要一上来讲模型参数。

## 2. 政策与准入要素

### 2.1 CCAR-92

民用无人驾驶航空器运行安全管理规则（内部 RULE-001）。覆盖：运行分类、平台功能、适航衔接、运营评估、C2、地区局职责等。`FACT`（规章存在与章节角色）  
**完整条款适用以现行有效文本为准**；本页只做演示用索引。

### 2.2 UOM 平台

民用无人驾驶航空器综合管理平台：`https://uom.caac.gov.cn`。登记、空域查询、飞行活动、运营、动态数据等的**系统面**，不是“一个网页表格”。见 [08](./08-uom-system-map.md)。`FACT`

Tokfai 切入：帮客户在**本机**整理接口说明/填报清单/日志字段映射。**不代替客户登录 UOM，不代提交。**

### 2.3 实名登记

条例第九–十条等：唯一产品识别码、所有者实名登记。未登记飞行有公安处罚钩子。`FACT`  
演示问法：登记主体是个人还是单位？与运行人是否同一法人？

### 2.4 适飞空域

适飞 vs 管制/临时管制决定“能不能在该空域这样飞”。`FACT`（空域章存在）  
地方协调细节多为 `CASE`/`UNKNOWN`。不要承诺某工业园“默认适飞”。

### 2.5 网络识别 / 运行识别

条例识别信息要求；GB 46750 运行识别（生效窗口见来源册，内部 FUTURE/PARTIAL）。`FACT` 有标准；与 UOM 动态数据管道的工程对齐细节部分 `UNKNOWN`（[22](./22-decision-critical-unknowns.md)）。

演示：只追“广播/报送模块路径与字段名”，不宣称已符合 GB。

### 2.6 TC / PC / AC / OC

| 证件 | 解决什么 | 不解决什么 |
| ---- | -------- | ---------- |
| **TC** 型号合格证 | 设计批准：符合适航/环保要求（适用时） | 单机状态、生产体系、运行权 |
| **PC** 生产许可证 | 按批准质量体系生产 | 单机适航、空域 |
| **AC** 适航证 | 单机适航批准（标准或特殊） | 运营合格证、任意航线 |
| **OC** 运营合格证 | 运行人从事相应运行的资格（与运营规范绑定） | 替代适航；不等于空域批准 |

特殊适航证 ≠ 标准适航证。特许飞行证用于尚未取得适航证书等法定情形。`FACT` 见 [10](./10-airworthiness-system-map.md)。

中型、大型：设计/生产/进口/飞行/维修应申请适航许可。微/轻/小：条例路径为产品质量+强制性国标，**无需适航许可**。`FACT`

### 2.7 特定类运行

CCAR-92：开放类 / 特定类 / 审定类（92.7 等）。`FACT`  
特定类：除一般要求外需风险缓解；常与运营安全评估、运营合格证路径相连。  
**不要**把“中型”自动等于“特定类”（内部反混淆见 [04](./04-regulatory-dependency-graph.md)）。

### 2.8 运营合格证

条例第十一条；CCAR-92 运营评估/颁证。常规农用（条件满足时）可有无需运营合格证的例外。`FACT`  
过渡特殊适航**支持**需要运营合格证的特定类运行，**不是**运营合格证本身。[12](./12-2026-transition-window.md)

### 2.9 2026 过渡窗口

交叉条件（须**同时**满足，`FACT`）：

- 中型或大型民用无人驾驶航空器系统
- 2024-01-01 **以前**已经设计定型
- **不进行设计更改**
- 运行人按规需申请运营合格证从事**特定类运行**
- 局方接受的安全评定
- 使用限制下取得**特殊适航证**
- 政策有效至 **2026-11-26**；该日后 AC 口径不再受理依安全评定的特殊适航证申请

新设计、改了设计、微轻小、不走该运营路径者：**不适用**。详见 [12](./12-2026-transition-window.md)。

### 2.10 标准场景 / 特定场景

规章存在开放/特定/审定及标准场景用语。`FACT`  
**完整公开标准场景目录**内部仍为硬 `UNKNOWN`（[22](./22-decision-critical-unknowns.md)）。  
对客户只说：以局方现行清单与运营规范记载为准，Tokfai 不编造场景目录。

## 3. 客户痛点（准入链）

| 痛点 | 典型表现 |
| ---- | -------- |
| 证与运行缠在一起 | 有 TC 新闻仍无法商业飞 |
| 过渡窗口误读 | 把 2026-11-26 当成“所有无人机截止日期” |
| UOM 当成唯一审批 | 忽略空域、保险、地方协调 |
| 材料很厚仍被退 | 缺的是门类证据而非页数 |
| 主体错位 | 设计单位的证不能当运行人的证用 |

## 4. Tokfai 切入点

| 环节 | 可做 | 不可做 |
| ---- | ---- | ------ |
| 问诊 | 按 G0–G11 收集事实字段 | 出具法律意见 |
| 材料辅助 | 在本机整理申请章节提纲、缺口清单 | 登录 UOM / 代提交 / 保证批准 |
| 工程对照 | 把“识别/动态数据/C2/应急”追到文件路径 | 宣称符合 CCAR 条款 |
| 过渡窗口 | 用 §2.9 清单做**资格核对提问** | 替局方认定“定型日期/是否设计更改” |
| 证件矩阵 | 帮客户分 TC/PC/AC/OC 缺哪张 | 把媒体“获适航”映射成具体证 |

本地工具仍由 Codex CLI 执行。

## 5. 演示问题清单

1. 航空器在登记上的分类是哪一档？依据哪份规格？
2. 是否中大型、是否需要适航许可？
3. 若谈 2026 过渡：定型是否在 2024-01-01 前？有无设计更改？是否特定类+运营合格证路径？
4. 运行人是否已有运营合格证及运营规范类别？
5. UOM 上登记/申请/动态数据，卡在哪一屏（只问状态，不录账号）？
6. 识别与动态数据，工程上对应哪几个仓库路径或 ICD？（固定范围 Read）
7. 上次申请退回意见是适航、空域、格式还是运行评估？

---

## 6. 销售问法

1. “获适航”具体是 TC、PC、特殊适航证、标准适航证，还是特许飞行证？
2. 商业合同里的“明年开通航线”，对应哪一个 Gate 仍是红灯？
3. 材料工作是缺编写人力，还是缺构型/试验证据？
4. 安全评定/试飞科目包能否在本机打开（不上传）？
5. 第一场做证件问诊，还是做飞控四文件链？（通常后者更适合证明 Tokfai）

---

## 7. 成交抓手

- **拆链**：一次会议把“飞不了”变成可指派的 Gate 列表。  
- **过渡窗口清单**：存量中大型客户有明确时间压力（仍须客户自己满足全部条件）。  
- **本机材料工作区**：敏感审定包不出门。  
- **与律所/适航代表分工**：他们出正式符合性立场；Tokfai 做出示路径的草稿与追溯。

| 项 | 边界 |
| -- | ---- |
| 标准场景目录 | `UNKNOWN` — 禁止现场背目录 |
