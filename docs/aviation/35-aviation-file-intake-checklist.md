## 1. 首次接触要哪些文件

按层收集。一次不要开口要“全部资料室”。先 **必须**，再按卡点加 **重要**。

### 必须（MUST）— 没有则只能做教学演示或冷处理

| ID | 文件 | 层 | 用途 |
| -- | ---- | -- | ---- |
| M1 | 书面授权范围（目录/文件名清单，可一页 Word） | — | 合法打开边界 |
| M2 | 机型/项目一句话 + 法定分类（微轻小中大，若已知） | L3/口头 | 选对故事，避免拿消费机讲 TC |
| M3 | 当前卡点：申请退回 / 联试 / 适航会 / 排故（选一） | — | 选工作流 |

无 M1：不打开客户树。无 M3：不约 30 分钟以上。

### 重要（IMPORTANT）— 有则能做资料体检；缺则降级

| ID | 文件 | 层 | 优先给谁 |
| -- | ---- | -- | -------- |
| I1 | 飞行活动申请表或最近一次退回意见（PDF/Excel） | L3 | 运营商/集成商 |
| I2 | UOM/运行手册相关章节或字段说明 | L2 | 平台/运行 |
| I3 | ControlLaw 相关 ≤4 个源文件路径 | L4 | 整机/飞控 |
| I4 | 符合性矩阵或需求 ID 表（Excel） | L3/L5 | eVTOL/适航 |
| I5 | 最近一份试验/HIL 报告封面+科目表 | L5 | 试验/试飞 |
| I6 | 现行适用的法规/AC **客户正在用的那一版** PDF | L1 | 合规 |

### 可选（OPTIONAL）

| ID | 文件 | 层 |
| -- | ---- | -- |
| O1 | SOP/检查单 | L6 |
| O2 | ICD / 动态数据字段表 | L2/L4 |
| O3 | 销售 PPT（仅作冲突检测） | L7 |
| O4 | 日志一小段可打开样本 | L5 |
| O5 | Simulink 生成代码目录说明 | L4 |

军警消防：仅民用非密清单；涉密立即停止（[30](./30-first-10-calls-battlecard.md)）。

## 3. 对应销售提问话术

短句，一次问一个。不要说“把代码包发我”。

| 文件 | 怎么问 |
| ---- | ------ |
| M1 | 演示或体检时，能不能先写四个文件名在纸上？我们只打开纸上这些。 |
| M2 | 这机是微轻小还是中大？不确定也行，别按宣传口径。 |
| M3 | 这周最痛的是申请退回、联试说不清，还是试验对不上代码？ |
| I1 | 退回意见能不能本机打开？不用发给我。 |
| I2 | 手册里动态数据或识别那一节，文件名叫什么？ |
| I3 | 姿态入口和控制分配大概在哪两个 `.c`？指得到就行。 |
| I4 | 矩阵在 Excel 里有没有需求 ID 列？ |
| I5 | 最近一次 HIL/试飞报告，科目表在第几页？ |
| I6 | 你们桌上那本现行规章 PDF 是哪年印发的？以你们那本为准。 |
| O3 | PPT 先不用。有证件和申请表更有用。 |

对方要发网盘：用 [31](./31-aviation-sales-scripts.md)「不能给源码」回复，改成本机目录。

## 4. 文件缺失时的降级演示

| 缺什么 | 演示怎么降 | 当场能交付 |
| ------ | ---------- | ---------- |
| 无任何客户文件 | **synthetic 四文件链** 30 分钟 | 方法证明；不谈该机符合性 |
| 有申请表无代码 | 只做 L3 栏位清单 + 缺口（无函数） | “表上写了什么、缺哪类证据” |
| 有代码无 PDF | 只做飞控路径表；法规句全标未打开 | 禁止引用记忆中的条款当 FILE |
| 有报告无矩阵 | 科目–版本表；不对需求 ID | 试验侧体检半份 |
| 有 PPT 无证件 | PPT 主张 vs “未提供证件页”冲突表 | 打假宣传，不评能否飞 |
| 有 UOM 口无手册 | 停止报送结论；建议先导出手册页 | 不编字段名 |
| CLI 装不上 | 我方投屏教学树 | 轻量档或取消（见 [32](./32-paid-pilot-offer.md) A） |

降级时口头：

> 今天缺 XX，所以只做到 YY。缺的不是我们“猜完”，是下一份授权文件。

## 5. 包装成「航飞资料体检服务」

对外一句话：

> 在你们电脑上，把申请表、手册、代码、试验报告对成一张**证据链表**（文件名/页码/字段/函数）。不上传资料室，不代替局方批准。

### 体检产出（给客户看的目录）

1. 打开文件清单（名+层 L1–L7）  
2. 证据链表（[34](./34-pdf-to-evidence-chain.md) 行格式）  
3. 冲突：宣传 vs 申请 vs 代码 vs 试验  
4. 缺口：申请有、文件无 / 文件有、申请无  
5. 建议核对清单（ADVICE）  
6. 明确**非**适航结论、**非**飞行批准  

### 与试点档对齐

| 体检深度 | 建议试点档 |
| -------- | ---------- |
| 只有教学树 + 讲解格式 | 免费演示或 A 轻量 |
| 申请表/手册栏位级 | A 或 B（无代码则缩范围） |
| 四文件飞控链 | B 工程链路 |
| 链 + 矩阵或日志 | C 团队协同 |

报价数字只在演示后按 [32](./32-paid-pilot-offer.md) 出，本页不对外报死价。

### 服务边界（写进体检封面）

```text
Tokfai：路由 / 计费 / 日志稳定性
Codex CLI：本机读文件
不保存客户资料室副本
不承诺审批结果
不把常识写成文件结论
```

### 销售收口

> 资料体检 = 把你们已经有的 PDF 和代码，变成能上会的指针表。  
> 文件越齐，表越硬；文件越缺，我们越只演示方法，不编条款。
